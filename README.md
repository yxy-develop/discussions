<h1 align="center">Yxy Discussions</h1>

<p align="center">The organization-wide conversation about the Yxy language, its compiler and its tools.</p>

This repository is the public source for organization-wide
[Yxy Discussions](https://github.com/orgs/yxy-develop/discussions). It connects
the language specification, the compiler and toolchain, the standard library,
the documentation, the website and the Homebrew tap without splitting
conversations into isolated forums.

## Start a conversation

- **Announcements:** official project news.
- **General:** conversation that does not fit a narrower category.
- **Q&A / Help:** usage questions about the language, the compiler and its tools.
- **Ideas:** early suggestions and project direction.
- **RFC / Proposals:** concrete changes to the language, the standard library,
  the tools or a JSON document that need design review; a change to the
  language becomes a recorded decision in [spec](https://github.com/yxy-develop/spec).
- **Development:** cross-repository implementation coordination.
- **Documentation:** the guide, the standard library reference, examples, and
  corrections.
- **Releases:** release notes, compatibility, and upgrade questions.
- **Contributing:** help finding and completing a contribution.

Use the affected repository's Issue tracker once work has a defined outcome and
acceptance criteria. Issues record work. Discussions record conversation.

## Where things live

| Repository | Responsibility |
| --- | --- |
| [yxy](https://github.com/yxy-develop/yxy) | Compiler and toolchain, the standard library, and the state of every requirement (`docs/implementation/STATUS.md`) |
| [spec](https://github.com/yxy-develop/spec) | Language specification and language decisions |
| [yxy.dev](https://github.com/yxy-develop/yxy.dev) | The website, [yxy.dev](https://yxy.dev), and the [documentation](https://yxy.dev/docs) it renders |
| [homebrew-tap](https://github.com/yxy-develop/homebrew-tap) | Homebrew formula for `yxy` |

## Engineering history

Defined work is recorded in Issues that cite full commit SHAs. A historical
claim without technical evidence is marked `needs-verification`, never
completed by assumption.

Read the organization-wide
[Engineering Traceability Policy](https://github.com/yxy-develop/.github/blob/HEAD/docs/ENGINEERING_TRACEABILITY.md),
[contribution guide](https://github.com/yxy-develop/.github/blob/HEAD/CONTRIBUTING.md)
and [support policy](https://github.com/yxy-develop/.github/blob/HEAD/SUPPORT.md).

## Security and conduct

Never disclose a vulnerability in Discussions. Use the affected repository's
private security advisory, as the
[security policy](https://github.com/yxy-develop/.github/blob/HEAD/SECURITY.md)
describes. Participation follows the
[Yxy Code of Conduct](https://github.com/yxy-develop/.github/blob/HEAD/CODE_OF_CONDUCT.md);
conduct reports go to [contact@yxy.dev](mailto:contact@yxy.dev).
